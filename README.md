# HowDoI

<!-- release-version: 0.1.17+18 -->

离线优先的个人旅行路书，当前版本 **0.1.17（构建 18）**。Windows 用于规划，Android 用于随身查看和修改；两端共用 Flutter 页面与业务规则。

## 功能

- 旅行、灵活日期和每日时间线；无出发日期也可按第 N 天安排。
- 航班、铁路、交通移动、住宿、游览等行程；跨日到达、多晚住宿、完成勾选、备注和排序。
- 独立旅行准备清单，支持截止日期、完成进度和手动排序。
- 内联录入多笔预计预算，展开即可填写币种、金额与分类；空白占位不入账，0 与未估算分开，按原币种汇总，不换算汇率。旧费用名称仍保存在数据中。
- 旅行总览、地点到访顺序和可选地图分享链接绑定。
- Windows 与 Android 共同支持：行程卡片和旅行总览点击地点名称打开已保存原链接；改名后仍可打开并提示核对。搜索地图偏好独立，只影响后续搜索，不改写原链接。
- 游览／活动支持独立标题与多个有序地点，可逐个更名、绑定、上移/下移、解除或移除。交通保留起终点，住宿保留单地点；历史单地点自动兼容读取。
- 同旅行内相同名称（仅忽略首尾空白）可复用唯一、无需核对的绑定；保存前预览数量与范围，同名歧义需手动选择，主动解除不自动绑回。跨行程补齐采用版本检查和原子保存。
- Windows 宽窗口中的地点绑定/更换在右侧编辑区完成，导航和中央行程保持可见，返回保留草稿及滚动位置；窄窗口与 Android 保留独立页面。确认后仍需保存行程。
- Windows 使用默认浏览器搜索 Google、百度或高德；Android 使用外部地图搜索、系统分享接收或粘贴。绑定页以地点名称、分享内容、可选经纬度为主，搜索与地址/来源按需展开；不请求 Nominatim。
- 两端当天页面显示可折叠 OSM 标点地图，按原行程与活动地点顺序编号；重复坐标可分别查看到访，缺坐标显示 X/Y 与补充入口。只画标点，不算路线或耗时。
- 手工经纬度为 Google 复制的 WGS84“纬度，经度”，与原链接分别保存；更换链接必须明确保留或清除已有坐标，历史 previousPosition 不自动启用。
- 活动类型按本机所有有效旅行中未删除行程的类型数量排序，同次数沿用固定顺序；菜单打开时固定，下次打开才刷新，不增加计数或同步状态。
- 同一 Wi-Fi 下 Windows 服务端与 Android 客户端扫码/文本配对、双向同步；离线仍可编辑。
- JSON 备份导入导出、未保存编辑保护、Windows 应用内更新。

目前不包含自动规划、实际开支、SPSir 联动、云同步或离线地图下载。

## 安装与使用

从 [GitHub Releases](https://github.com/K1TAproject/HowDoI/releases) 下载已发布文件；本地构建不代表已经发布到 GitHub。

- Windows 11：`HowDoI-0.1.17-windows-x64-setup.exe`，直接安装；另提供 ZIP 便携包。
- 协议 7（自 0.1.16 起）：同步/备份协议 7 防止旧客户端丢失独立坐标。
- Android ARM64：`HowDoI-0.1.17-android-arm64.apk`，允许相应安装来源后安装；升级沿用原签名，不要先卸载旧版。
- 首次手机配对使用空白测试数据，从电脑同步；不要先导入同一旅行备份造成副本。
- 详细操作见 [使用说明](docs/使用说明.md)，本版变化见 [版本更新说明](RELEASE_NOTES.md)。

## 数据、安全与限制

数据保存在本机 SQLite。同步采用 HTTPS 和证书指纹验证，按整条记录的更新时间合并；准备清单属于旅行记录，两端同时离线修改同一旅行可能互相覆盖。未保存草稿不参与同步。多个地点仍属于同一条行程：两端同时修改同一行程的不同地点，较新整条记录仍可能覆盖另一端；没有字段级合并。当前同步及备份协议为 7，兼容读取备份格式 1–7；两端必须升级至 0.1.16 或以上的兼容版本，旧客户端在更换绑定时可能清除新增坐标，协议不兼容时拒绝同步而非丢弃字段。不要用旧程序打开新版数据目录。

地点关联随行程备份和同步，本机配对凭据、待绑定目标、分享收件箱及搜索缓存不进入旅行备份。外部链接仅识别明确支持的百度/Google/高德 HTTPS 来源，不抓取网页、不解析短链接、不把视角中心当作坐标。当前有效位置单独保存在 position（lat/lon、WGS84、来源及用户确认标记），用于当天地图；外部打开优先原链接。百度/高德链接不代表坐标来源，不能直接填其原生坐标。更换链接必须明确处理坐标；历史位置仅留作历史，不自动作为当前标点。修改地点文字后保留原链接并提示核对；确认仍是此地点、更换或解除都先写入草稿。活动标题不影响各地点绑定。分享确认只修改草稿，行程保存后才同步；系统回收后需重新选择或确认已保存行程，未保存草稿无法恢复。

两端当天地图使用 Flutter Map 和标准 OSM 瓦片，遵守 [OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)：固定应用 User-Agent、可见署名、内置 HTTP 缓存（128 MB 软上限）、只请求视野内瓦片、不提供预下载或离线地图。缓存留在本机，不进入旅行备份。无需地图密钥、收费套餐或自建服务器；不增加手机定位权限。OSM 为尽力服务，可能超时或限制访问，不保证永久免费或无限可用。此前 v0.1.16 本机网络测试日本/欧洲瓦片返回有效 PNG，不代表国内直连或红米 K70 真机验证。

没有坐标时显示紧凑提示，不显示空地图；部分缺少/待核对坐标不影响其他标点。地图失败或 20 秒内未有瓦片加载时显示重试，原链接和文字路书仍可用。极区纬度超出底图投影范围时在边界显示并提示，保存值不改写。不恢复 Nominatim、反向查询、坐标自动解析、路线连线或跨坐标系转换。

此前 v0.1.13 在本机 Edge 验证过 Google、百度样本地点及网页搜索；高德短链打开官方网页后提示“未能获取到该地点信息”，搜索入口可打开但未确认结果列表。该次使用代理/VPN，不能据此保证当前网络、国内直连或手机可用。本版未重复进行真实浏览器与红米 K70 操作验证。HowDoI 保留原链接而不改写为其他来源。

## Windows 搜索标签页限制

当前默认浏览器 Edge 与项目 URL 启动器使用的 [Windows ShellExecuteW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew) 接口不提供标签页 ID、指定标签页导航或关闭状态。因而本版**不支持自动复用上一次地图搜索标签页**；是否新增标签页由浏览器决定，不能保证复用。

绑定界面可“复制搜索网址”，自行在已有标签页地址栏粘贴搜索；复制不会打开或控制浏览器。目标页仍打开、已关闭、已手动转往其他页面时，HowDoI 都不检测或接管；切换地图来源只改变下次搜索网址。已绑定地点始终打开原链接，不受此影响。

要可靠管理专属标签页，需要另行设计用户安装的浏览器扩展等集成（例如 [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)）；本轮不增加扩展、浏览器监控、模拟快捷键、未公开接口或内嵌浏览器。核对公开接口不等于完成上述标签页状态的实测。

## 本地开发

使用 Flutter / Dart、SQLite；依赖锁定在 `pubspec.lock`。Windows 构建需要 Visual Studio C++ 桌面开发组件和 NSIS；Android 需要完整 JDK（含 jlink）、Android SDK 和原签名。

本项目脚本使用 `.tools/flutter`、`.tools/android-sdk`、`.tools/nsis`，JDK 路径写入 `.local/java-home.txt`。工具、签名及本机配置均不提交。Android 原签名在 `.local/`，必须另外安全备份；换电脑时先恢复原签名，不能为已发布应用重新生成。

```powershell
.\scripts\Flutter.ps1 pub get
.\scripts\Flutter.ps1 analyze --no-pub
.\scripts\Flutter.ps1 test --no-pub
.\scripts\Build-Installer.ps1
.\scripts\Build-Android.ps1
```

`lib/` 为业务与界面，`test/` 为测试，`android/` 和 `windows/` 为平台工程，`assets/` 为运行资源，`scripts/` 为构建及隔离验证脚本。运行产物在 `dist/`，测试临时数据在 `work/`。

业务功能以 Windows 和 Android 共同开发、共同验收为原则；只为浏览器、Android 分享及桌面/触控布局保留必要平台差异。

## 每版发布流程

1. 在唯一版本来源 `pubspec.yaml` 更新补丁号与构建号。
2. 完整审阅本 README：同步版本标记、安装文件名、功能、平台支持、限制和构建方式，不能只替换版本数字。同步使用说明的受影响内容。
3. 重写单份 `RELEASE_NOTES.md`，写清本版新增、修复、兼容性、已验证和待验证事项；不生成“修改与验证.md”。
4. 运行检查及打包。脚本先校验 README 与更新说明的完整版本标记；成功后将说明复制到 `dist/HowDoI-版本-release-notes.md`，与安装包一起交付。脚本不会根据提交记录猜测功能或虚构验证结果。
5. 核对安装包签名、版本与验证结果，再单独发布安装包和版本说明到 GitHub Releases。`git push` 只上传源码，不上传安装包。

当前自动化测试和真机验证的边界见版本更新说明。发布前使用独立测试数据，不覆盖真实旅行数据。

## Git 上传范围

保留源码、平台工程、依赖锁文件、构建脚本、README、当前版本说明、使用说明和项目协作规则。历史需求/验证文档、设计草稿、工具链、安装包、临时数据和签名仅留本地。

```powershell
git add .
git commit -m "描述本次修改"
git push
```

忽略规则不清除远端历史提交；曾上传的文件仍可从历史中找到。不要强制添加私密配置或真实数据。

## v0.1.17 补充

Windows 当天地图可点击“展开地图”，在应用标题栏下铺满可用区域；“返回行程”恢复原旅行、日期、滚动位置和编辑草稿，不触发保存。从标点进入编辑仍执行未保存提示。Android 地图布局不变。

同名地点复用现在也补齐已有相同原链接但缺少坐标的地点。只使用唯一、已确认且无需核对的当前坐标；不同来源/链接或不同坐标有歧义时不自动补齐，已有坐标不覆盖，主动解除标记继续生效。与 URL 一样在保存前预览并原子提交，两端共享规则。

Windows 打包前用 `scripts/Assert-WindowsPayload.ps1` 核对精确文件清单；发现额外文件即中止，不会偷偷删除本地文件。增加运行资源或依赖时须审阅并更新该清单。上传范围需同时检查索引、历史和远端；忽略规则不能撤回历史文件。审计范围与限制见当前版本说明。
