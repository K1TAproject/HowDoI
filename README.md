# HowDoI

<!-- release-version: 0.1.13+14 -->

离线优先的个人旅行路书，当前版本 **0.1.13（构建 14）**。Windows 用于规划，Android 用于随身查看和修改；两端共用 Flutter 页面与业务规则。

## 功能

- 旅行、灵活日期和每日时间线；无出发日期也可按第 N 天安排。
- 航班、铁路、交通移动、住宿、游览等行程；跨日到达、多晚住宿、完成勾选、备注和排序。
- 独立旅行准备清单，支持截止日期、完成进度和手动排序。
- 按原币种统计预计预算与分类组成，不换算汇率；零费用和未估算分别显示。
- 旅行总览、地点到访顺序和可选地图分享链接绑定。
- Windows 使用默认浏览器搜索 Google、百度或高德地图，粘贴分享内容、核对后写入草稿，再保存行程。当天与总览使用地点卡片，显示原链接、来源、名称、地址和所属行程；重复到访分别展示，不内嵌地图或绘制路线。
- Android 不内嵌地图、不请求 Nominatim。编辑页“绑定起点 / 绑定终点 / 绑定地点”打开外部百度或 Google 搜索（另可选高德网页），选定后分享至 HowDoI（或主动粘贴分享内容），确认目标与原链接写入草稿，保存后卡片“打开地图地点”。历史可靠坐标仍支持导航，只有文字或失效位置则搜索；不依赖电脑。
- 同一 Wi-Fi 下 Windows 服务端与 Android 客户端扫码/文本配对、双向同步；离线仍可编辑。
- JSON 备份导入导出、未保存编辑保护、Windows 应用内更新。

目前不包含自动规划、实际开支、SPSir 联动、云同步或离线地图下载。

## 安装与使用

从 [GitHub Releases](https://github.com/K1TAproject/HowDoI/releases) 下载已发布文件；本地构建不代表已经发布到 GitHub。

- Windows 11：`HowDoI-0.1.13-windows-x64-setup.exe`，直接安装；另提供 ZIP 便携包。
- Android ARM64：`HowDoI-0.1.13-android-arm64.apk`，允许相应安装来源后安装；升级沿用原签名，不要先卸载旧版。
- 首次手机配对使用空白测试数据，从电脑同步；不要先导入同一旅行备份造成副本。
- 详细操作见 [使用说明](docs/使用说明.md)，本版变化见 [版本更新说明](RELEASE_NOTES.md)。

## 数据、安全与限制

数据保存在本机 SQLite。同步采用 HTTPS 和证书指纹验证，按整条记录的更新时间合并；准备清单属于旅行记录，两端同时离线修改同一旅行可能互相覆盖。未保存草稿不参与同步。当前同步及备份协议为 5，兼容读取备份格式 1、2、3、4、5；两端必须升级至 0.1.13 或以上的兼容版本，旧客户端无法读取新增高德来源，协议不兼容时拒绝同步而非丢弃字段。不要用旧程序打开新版数据目录。

地点关联随行程备份和同步，本机配对凭据、待绑定目标、分享收件箱及搜索缓存不进入旅行备份。外部链接仅识别明确支持的百度/Google/高德 HTTPS 来源，不抓取网页、不解析短链接、不把视角中心当作坐标。Windows 本轮不绘点；更换旧坐标时保留历史位置，但不把它用于新链接导航。修改文字后提示核对。分享确认只修改草稿，行程保存后才同步；系统回收后需重新选择或确认已保存行程，未保存草稿无法恢复。

两端均不再使用 Nominatim 或内嵌地图，不请求内部地点搜索与瓦片服务；旧坐标数据和来源仍保留。未绑定、断网、外部网页故障不影响文字路书和编辑。仅使用公开网页调起能力，不需要 API 密钥、付费套餐或自建服务器；外部网站可能要求登录或限制访问，不保证全部地点和链接均可用。名称、地址由用户核对，不从网页隐藏内容或短链接推断坐标。

本机 Edge 已验证 Google、百度样本地点及网页搜索；高德短链打开官方网页后提示“未能获取到该地点信息”，搜索入口可打开但未确认结果列表。用户当前使用代理/VPN，不能据此保证国内直连或手机可用。HowDoI 保留原链接而不改写为其他来源。

## 本地开发

使用 Flutter / Dart、SQLite；依赖锁定在 `pubspec.lock`。Windows 构建需要 Visual Studio C++ 桌面开发组件和 NSIS；Android 需要完整 JDK（含 jlink）、Android SDK 和原签名。

本项目脚本使用 `.tools/flutter`、`.tools/android-sdk`、`.tools/nsis`，JDK 路径写入 `.local/java-home.txt`。工具、签名及本机配置均不提交。Android 原签名在 `.local/`，必须另外安全备份；换电脑时先恢复原签名，不能为已发布应用重新生成。

```powershell
.\scripts\Flutter.ps1 pub get
.\scripts\Flutter.ps1 analyze --no-pub
.\scripts\Flutter.ps1 test --no-pub
.\scripts\Build-Installer.ps1
.\scripts\Build-Android.ps1
```

`lib/` 为业务与界面，`test/` 为测试，`android/` 和 `windows/` 为平台工程，`assets/` 为运行资源，`scripts/` 为构建及隔离验证脚本。运行产物在 `dist/`，测试临时数据在 `work/`。

## 每版发布流程

1. 在唯一版本来源 `pubspec.yaml` 更新补丁号与构建号。
2. 完整审阅本 README：同步版本标记、安装文件名、功能、平台支持、限制和构建方式，不能只替换版本数字。同步使用说明的受影响内容。
3. 重写单份 `RELEASE_NOTES.md`，写清本版新增、修复、兼容性、已验证和待验证事项；不生成“修改与验证.md”。
4. 运行检查及打包。脚本先校验 README 与更新说明的完整版本标记；成功后将说明复制到 `dist/HowDoI-版本-release-notes.md`，与安装包一起交付。脚本不会根据提交记录猜测功能或虚构验证结果。
5. 核对安装包签名、版本与验证结果，再单独发布安装包和版本说明到 GitHub Releases。`git push` 只上传源码，不上传安装包。

当前自动化测试和真机验证的边界见版本更新说明。发布前使用独立测试数据，不覆盖真实旅行数据。

## Git 上传范围

保留源码、平台工程、依赖锁文件、构建脚本、README、当前版本说明、使用说明和项目协作规则。历史需求/验证文档、设计草稿、工具链、安装包、临时数据和签名仅留本地。

```powershell
git add .
git commit -m "描述本次修改"
git push
```

忽略规则不清除远端历史提交；曾上传的文件仍可从历史中找到。不要强制添加私密配置或真实数据。
