# HowDoI v0.1.6 修改与验证

日期：2026-10-15。统一版本：`pubspec.yaml` 中的 `0.1.6+7`。本轮仅修复 Windows 更新流程；安卓、SPSir、实际开支暂缓，没有数据库迁移或新增依赖。工作区已有图标改动原样保留，不属于本轮修复。

## 原因与现场核对

旧 `UpdateDialog.install` 对所有 Windows 运行方式都下载 ZIP，部署到应用数据目录 `updates/versions/<版本>-<UUID>/howdoi.exe`，启动成功后退出旧程序。它既不覆盖原安装，也不更新原安装快捷方式，因此“本次打开新版”和“以后通过快捷方式打开新版”不是同一件事。

只读检查发现，现有桌面和开始菜单的 `HowDoI.lnk` 都指向 `C:\Users\86159\AppData\Local\Programs\HowDoI\howdoi.exe`，该文件版本为 `0.1.5+6`。修复期间没有运行安装程序覆盖此位置，也没有改写这些快捷方式或真实数据库。

## 修复内容

1. 安装身份通过当前 EXE 路径、原安装注册信息、桌面/开始菜单目标及卸载程序存在性核对。独立便携副本不因电脑另有安装版而被当作安装版；旧 `updates/versions/` 运行实例可以回到原安装。多个不一致候选且无法唯一判断时停止自动选择。
2. 安装版从同一 GitHub Releases 获取 `HowDoI-<版本>-windows-x64-setup.exe`；便携版仍获取 ZIP。不回退到用 ZIP 冒充安装版更新。下载仍限制大小、来源和重定向，校验 SHA-256；助手安装前再次校验文件和版本。
3. 界面区分“下载完成，等待确认安装”和真正的安装完成。下载后另有安装确认，可取消。打开关于和开始安装均执行未保存保护。确认后生成数据库快照，启动助手并确认助手就绪，然后关闭数据库及当前进程；助手等待进程退出后才运行安装器。
4. EXE 安装器通过 NSIS `/D=` 沿用原目录，支持中文和空格路径；静默安装只发生在应用内明确确认之后。桌面和开始菜单快捷方式均由安装器刷新。安装器文件、注册信息或快捷方式写入错误返回失败，不继续当作成功。
5. 安装助手在改动前保留原程序文件、快捷方式及安装注册信息。失败时尝试恢复，保留回滚副本和错误记录；真实旅行数据库不参与覆盖或回滚。原目录额外用户文件保留。
6. 只有安装程序正常退出、原目录 EXE 完整版本匹配、两个快捷方式目标正确、数据库副本试启动成功，才写入 `installer-result.json` 的 completed 状态并打开新版。其他状态为 waiting/installing/failed；关于页面显示历史安装实际结果。
7. 旧逻辑已启动独立目录中的新版时，即使 GitHub 同版本也可提供 EXE 安装修复原入口，不误称发现了更高版本。旧 `installedUpdate` 设置只显示为历史便携位置，不再作为原安装完成的证据。

程序快照和回滚文件保存在数据目录的 updates 下；安装包和助手不删除真实旅行数据库、准备清单、预算、备份或用户设置。若系统权限或文件占用连恢复也阻止，会明确记录回滚未完成及副本位置，不宣称成功。

## 已验证

- Flutter 静态检查无问题；常规全量测试 69 项通过、3 项 opt-in 测试跳过。日志：`work/analyze-0.1.6.log`、`work/tests-0.1.6.log`。
- HTTP 本地服务测试验证安装版选择 EXE、便携版选择 ZIP、同版本入口修复、缺包/缺校验、HTTP 错误、下载截断/超长/校验失败；失败不改变原程序文件。
- 安装身份测试覆盖正常安装、自定义路径、无关便携副本、旧独立更新目录、无安装候选和多个候选。
- Widget 测试验证安装前未保存检查拒绝时不出现安装确认；取消确认不开始安装、不改变 Store。原有旅行、准备清单、预算、日期、排序及未保存保护回归通过。
- `Test-InstalledUpdate.ps1` 在 `work/update-install-<随机ID>/Custom 安装目录` 建立旧 0.1.5 安装环境，再用 0.1.6 进行真实 NSIS 更新。测试安装器只通过编译定义把注册表键和快捷方式位置重定向到独立测试范围；正式安装器没有这些测试路径。
- 更新完成后分别通过测试桌面和测试开始菜单的 `.lnk` 实际启动程序（使用独立数据库探测参数），均确认 `0.1.6+7` 原目录程序可运行。原目录额外文件保留；数据库原文件哈希未变，重新读取后旅行、准备事项、预算金额和设置一致。
- 故障注入覆盖安装退出 1（取消/失败）、程序文件部分覆盖后退出 17、返回 0 但快捷方式缺失：均报告 failed，恢复原 EXE 哈希和快捷方式。安装前 SHA-256 不符未改动安装或数据库。这些是可复现的故障注入，不是人为破坏真实安装或真实磁盘故障。
- 额外的最终发布 EXE 测试使用数据库副本启动，坏数据库安全拒绝，原数据不变。日志：`work/release-smoke-0.1.6.log`；安装隔离日志：`work/installed-update-0.1.6.log`。

## 未验证边界

- 未发布 GitHub Release，真实 GitHub 下载→确认→关闭旧窗口→后台安装→重新打开的在线完整链路仍需在发布后验证。网络响应和下载失败使用本地 HTTP 服务验证，不冒充线上成功。
- 正式桌面/开始菜单的用户现有入口仅只读核对；实际安装及快捷方式启动使用重定向的隔离环境。没有在用户真实数据库上执行升级。
- 安装取消由界面取消测试和安装退出码注入验证；没有操作真实用户安装向导。真实断电、磁盘损坏、杀毒软件阻止和权限异常的所有组合未验证。
- 便携版独立目录部署与试启动回归通过；便携版不会自动改写原便携目录或无关快捷方式。

## 发布和首次使用

交付 `dist/HowDoI-0.1.6-windows-x64-setup.exe`、ZIP 与 `dist/SHA256SUMS.txt`。版本完整值保留为 `0.1.6+7`，关于主要显示 `v0.1.6`。

旧 0.1.5 二进制仍包含旧更新逻辑。首次使用修复版可运行本版 EXE 安装包，选择原安装目录；以后应用内更新会沿用原位置。若先由旧版 ZIP 流程进入 0.1.6 的独立更新目录，可在 GitHub 发布同版本 EXE 后再次检查更新，完成原入口修复。

复现命令：

```powershell
./scripts/Flutter.ps1 analyze --no-pub
./scripts/Flutter.ps1 test --no-pub
./scripts/Build-Installer.ps1
./scripts/Flutter.ps1 test --no-pub --dart-define=HOWDOI_RELEASE_SMOKE=true test/release_smoke_test.dart --plain-name 'actual packaged executable'
# 保留 dist/HowDoI-0.1.5-windows-x64.zip 作为旧版程序载体：
./scripts/Flutter.ps1 test --no-pub --dart-define=HOWDOI_INSTALLER_SMOKE=true test/installed_update_test.dart
```
