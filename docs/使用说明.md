# HowDoI 0.1.16 使用说明（Windows / Android）

## 安装与升级

推荐直接双击 `dist/HowDoI-0.1.18-windows-x64-setup.exe`，按中文向导安装，无需手动解压。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\HowDoI`，无需管理员权限，可选择安装目录和桌面快捷方式；安装后可从开始菜单启动。安装前先保存行程并关闭 HowDoI。

Windows“已安装的应用”中可卸载 HowDoI，也可运行安装目录中的 `Uninstall.exe`。卸载只删除安装包内的程序文件与快捷方式，保留旅行数据库、备份、应用内下载版本及用户额外添加的文件。安装版应用内更新使用 GitHub Releases 中的 EXE 安装包；便携版使用 ZIP，不依赖开发电脑路径。

解压 `dist/HowDoI-0.1.18-windows-x64.zip`，保留全部文件，双击 `howdoi.exe`。程序数据仍保存在当前用户应用数据目录，与 0.1.0 相同。建议升级前先导出 JSON 备份。

从数据协议 1/2 首次升级时，会在数据库旁生成 `howdoi.db.pre-0.1.2-时间戳.db` 升级快照，然后继续使用原数据。原有座位、订单、时区等资料保留；时区不再作为录入选项，也不再自动换算票面时间。不要用旧程序直接打开已经由新版修改的数据；需要回退时应先保留当前数据，再恢复升级前快照。

Android 安装 `dist/HowDoI-0.1.18-android-arm64.apk`，允许本次安装来源安装应用；沿用原签名，可覆盖更新同包名旧版。不要卸载旧版来升级，卸载会删除手机私有数据。手机与电脑均使用 0.1.16 或之后兼容版本。安卓本轮不提供应用内更新。

## 安排行程

1. 创建旅行，只需旅行名称；出发日期用日历选择，也可留空，不要求填写总天数。
2. 左侧“添加日期”只添加并选中旅行日，不打开编辑。默认接在最晚的旅行日后，没有日期时从第 1 天开始。有出发日期时同时显示日历日期。随后点击当天右下角“添加行程”，行程自动归属所选日期。
3. 主动添加的空白日会保留，重开或备份导入后仍在；程序不自动生成中间空白日，也不压缩编号。旧版无日期记录通过当天页面的“为 N 条历史行程分配日期”处理，处理完入口自动消失，没有常驻“待安排”菜单。酒店若与旧退房日冲突，可补选退房日；原资料和预计费用保留。
4. 类型决定主要输入内容。标题可留空，交通自动使用路线或班次，其他行程使用地点、内容或类型名称。
5. 日期、时间和预计时长通过点击或触控选择。清空票面日期不会取消行程所属的旅行日；时间和预计时长可留空。所有票面时间按对应地点当地时间记录，不选择时区，不计算跨时区时长。
6. 填写后点击“保存行程”。切换行程或日期时，未保存的内容会提示保存、放弃或继续编辑。完成勾选与拖动顺序立即保存。

修改旅行出发日期时，未预订规划随旅行日顺延；已固定日期的预订保留票面日期，在卡片上显示与旅行日不一致的提示。请根据提示确认归属，程序不会静默重排已预订日期。

## 日期菜单与选择器

旅行和日期卡片右侧的“⋯”只操作该卡片，不切换当前选择。旅行设置从旅行卡片的“编辑旅行”打开；关于与更新仍在顶部。

有出发日期时，日期主标题为“10月14日 · 周三”，副标题显示第几天和年份，跨年不混淆。无出发日期时仍显示“第 N 天”。

- “调整日期”：预览当天开始的记录，选择目标日并确认。目标已有安排时提示合并，沿用时间与手动排序规则。记录的开始/结束旅行日整体平移；已预订的票面日期不变，出现差异时提示核对。不移动其他旅行日，不压缩编号。
- “删除日期”：主动添加且没有任何记录/关联的空白日立即删除，提供约 7 秒“撤销”，到期自动收起。撤销后立即关闭提示；连续删除时只保留最新一次的提示和撤销入口，不排队。提示到期不再修改数据。非空日默认移往另一日后删除；也可选择删除当天行程及日期，列出记录后再二次确认。
- 住宿覆盖、跨日到达属于关联安排，不能当成空白日。**必须先调整原行程的关联日期，才能删除该日期**，不会隐藏日期或误删其他日期开始的记录。调整日期时只移动当天开始的行程，其他日期开始的关联安排留在原处，预览会说明。
- 删除当前日期后选择后一个日期，没有后一个则选前一个；全部删除后显示添加日期空状态。

整个日期字段均可点击。日历在当前编辑区域内展开；靠近底部时向上或在编辑区域内部显示。先定位已有日期，无值时定位当前旅行日；可切换月份、点击年份快速选择年份，并用月份按钮打开月选择网格。点选一天即写入草稿并收起，仍需“保存行程”才持久化。

时间以 24 小时制的两列滚动列表选择，小时和分钟可点击、滚轮滚动，聚焦列后用方向键调整。任意分钟（如 09:37）均保留；“完成”才写入草稿，Esc/取消不改变原值，打开空字段不会自动写入 00:00。预计时长单独按小时和分钟选择，可超过 24 小时，已有更长时长保留。不会因到达时间较早而自行推断跨日，不恢复时区选择。

编辑区域滚动或窗口缩放时，选择器自动收起，避免悬空。宽窗口缩到窄窗口时草稿保留；Windows 关闭窗口也会检查行程未保存的修改。

## 查看与排序

当天使用紧凑时间线，保留小时标记，空闲时段压缩。卡片高度不代表实际耗时。

有开始时间的行程按时间排序；只有预约时间时按预约时间排序并标注“预约”。无时间行程可拖到任意位置，跟随前一个定时行程；前一个行程同日改时间时一起移动，但不获得虚构时间。前一个行程被删除或移到其他日期时，无时间行程保留在原日。

拖动不修改票面时间；不同时间的定时行程需修改时间来调整顺序。同一时间的行程可以手动调整顺序。备注默认显示一行，点击备注可展开全文。

## 各类行程

- 航班、铁路、长途汽车、轮渡：起终点、发到时间、班次直接显示在主页；登机口、检票口、站台、铁路车厢座位填写后直接显示。跨日到达在到达日显示关联信息，点击仍编辑原记录，不重复计算预算。换乘各段分别记录。
- 住宿：一次记录多晚，当晚住宿区域显示名称、地址、日期及晚数。退房当天不显示原酒店为当晚住宿，也没有“今日退房”提醒。只有填写计划入住/退房时间，才显示对应时间线节点；酒店规定的最早入住、最晚退房时间只作补充资料。
- 交通/移动：重点填写起点、终点、预计耗时。方式和线路可留空，适用于步行、公交、打车、自驾等；可从补充信息中选择已有地点以减少重复录入。
- 租车：一次记录取还车及整个租期，主页在取还车日分别显示节点，费用只计算一次。每天的驾车路线另外用交通/移动记录。
- 游览/活动、餐饮、购物、其他：可只写地点或安排内容，以及预计停留时长；不强求精确时间。预约场次和计划到达时间分开，开放时间不会自动成为计划时间。

补充资料和预计预算默认折叠，按需展开。旧记录中已有的额外信息仍可在补充区域编辑；旧时区值只保留在数据中。

## 预算

编辑行程时展开“预计预算”，直接填写内联的币种、金额和分类。首行币种预选旅行的默认预算币种；仅展开或保留空白占位不会生成记录。输入金额（包括 0）后成为费用行；若确实尚未估算，点击“记为未估算”。已存在费用行清空金额也表示未估算。通过“增加费用行”明确添加的行可留空金额，删除按钮只移除该笔费用草稿。

不再填写费用名称；明细使用所属行程的主要信息，旧费用名称继续保存在数据和备份中。币种、分类、金额随行程一起保存，取消编辑不修改已保存费用。各币种按原小数位分别汇总，不换算汇率，不生成跨币种总计；未知金额不视为零。修改默认币种只影响新费用行，不改变历史行。多地点活动仍只有原行程预算，住宿/跨日关联不重复计费。本版不增加实际开支。

## 界面与应用内更新

界面统一使用暗色黑蓝主题。宽度达到 1100 时使用左侧日期、中间行程、右侧编辑三栏；800–1099 时保留日期栏，编辑在独立页面打开；更窄时日期栏收进左上角菜单。当前日期有勾选标识，完成状态有勾选与删除线，错误有文字说明；输入框支持 Tab 焦点。系统文件选择窗口的外观由操作系统控制。Android 使用左上角菜单选择旅行、总览、预备工作和日期；编辑页在软键盘弹出时缩小可用区域，保存操作保留在底部。系统返回先关闭选择器，再按未保存提示离开编辑页。

右上角信息图标打开“关于 / 检查更新”。若正在编辑，先选择保存、放弃或继续编辑。程序会核对安装信息和快捷方式目标，并显示安装版或便携版更新方式。环境无法确认时停止更新。下载通过大小与 SHA-256 校验后，只显示“下载完成，等待确认安装”；点击“安装已下载版本”后仍可取消。

**安装版：** 从 GitHub Releases 获取 EXE 安装包。确认后保存数据库快照、关闭当前程序，安装助手等待进程退出，再将安装包部署到原安装目录（包括自定义目录），更新桌面与开始菜单快捷方式。安装程序退出成功后，还会核对原目录版本、两个快捷方式目标，并使用数据库副本试启动。全部通过才记录安装完成并打开新版。失败时尝试恢复原程序文件和快捷方式，真实旅行数据库、准备清单、预算与设置不参与覆盖。关于页面会显示上次实际安装结果。

**旧独立更新目录：** 若当前运行在 `updates/versions/` 下且能找到原安装，将按安装版处理；即使当前版本已是最新，也可从同版本 Release 获取 EXE 包修复原安装入口。有多个不一致的安装位置时停止自动选择。没有原安装记录时保持便携模式。

**便携版：** 继续使用 ZIP，校验后部署到数据目录的 `updates/versions/`，用数据库副本试启动。原便携文件夹保留，不改写与其无关的安装版快捷方式；新版目录与 `updates/启动已安装版本.cmd` 仍可使用。这不表示原便携目录已经被替换。

首次升级到修复版可直接运行本版 EXE 安装包，选择原安装目录。旧版应用本身仍含旧更新逻辑；若先通过旧逻辑进入本版的独立更新目录，需再次检查更新，使用同版本 EXE 完成原安装修复（要求 GitHub 已发布该 EXE 和校验信息）。

本地构建成功不等于已发布到 GitHub。没有正式 Release 时，检查结果不会声称“更新成功”。

## 同一 Wi-Fi 扫码配对与同步

1. 先升级 Windows 到本版并打开应用；电脑和手机连同一可信 Wi-Fi。首次测试用空白手机数据，不要先导入电脑备份（导入会创建独立副本）。
2. 电脑右上角“设备同步”→“连接手机”，显示二维码。手机同一入口→“扫描电脑二维码”，首次请求相机权限。拒绝权限时可展开“文本配对备用入口”，在电脑复制完整文本并安全传到手机粘贴，无需修改 JSON。
3. 手机验证电脑 HTTPS 证书指纹、连接凭据、时间和协议后才保存配对。出现“已同步”表示本次双向合并及确认完成；“连接中”不代表同步完成。二维码和文本含连接凭据，请勿发送到公开聊天、日志或仓库。
4. 此后配对自动保存。手机打开、回到前台及保存修改时会尝试同步，前台每约 10 秒重试；电脑保持应用运行即可，可以切换窗口或最小化。电脑关机/休眠或手机后台/锁屏时不保证实时同步。断网仍可查看编辑；回来后可点“立即同步 / 重试”。
5. 电脑地址变化时手机尝试从各网卡广播重新发现同一证书的电脑；发现失败保留原数据及配对。应用显示待同步、离线或失败原因，以及最近一次确认同步的时间。撤销配对会失效旧凭据，需要重新扫码，不会删除旅行。

同步自己的全部旅行，采用整条记录最新更新为准；删除会传播。准备清单整体属于旅行记录，两端同时离线修改旅行/准备清单可能由较新旅行记录覆盖。请先保存；未保存草稿不会自动提交，远程记录变动后本地旧编辑页保存会提示核对。

数据协议为 7，拒绝同步协议 1–6；新增安全握手要求电脑支持本版，不支持时提示更新电脑。备份兼容格式 1–7，配对凭据、证书和同步设置不写入备份。

**故障排查**：不要关闭 Windows 防火墙。在系统提示中仅允许 HowDoI 访问可信专用网络；如需手动规则，限定程序及专用网络的 TCP 47821、UDP 47822。检查两端同一 Wi-Fi、电脑程序仍在运行，排除访客网络/AP 隔离和 VPN 路由。时间相差超过五分钟或记录时间超前时先校准两端系统时间，不会假报成功。证书不匹配时核对电脑，确认是自己的电脑后重新扫码。相机拒绝后可使用文本配对，或在系统应用权限中允许相机后重试。相机扫描采用随 APK 打包的识别库，不要求 Google Play 下载模型。

测试时先在电脑建立专用测试旅行，手机不导入同一旅行副本；依次验证电脑→手机、手机→电脑、重复同步、删除、离线修改、Wi-Fi 恢复及前后台切换，再用于正式记录。重要旅行先导出备份。

## 备份与恢复

旅行卡片右侧“⋯”可编辑旅行、导出本次旅行、删除旅行。右上角菜单可导出全部旅行或导入备份。导入会先显示旅行数量，再创建新副本；不覆盖现有行程、不导入配对凭据。原备份可以手动保存到百度网盘。

旅行和活动删除会同步，请按需要先导出备份。本版没有回收站或旧版本历史。


## 旅行预备工作（v0.1.5）

左侧日期列表前的“预备工作”显示完成数量/总数量，不占用旅行日，没有出发日期也可以使用。输入事项名称后按回车或点击加号即可创建；点击事项，在右侧面板（窄窗口为编辑页）补充截止日期、备注，最后保存。截止日期通过日历选择，与旅行出发日期独立。

勾选完成后事项进入底部“已完成”折叠区。未完成和已完成事项均可在各自区域通过右侧手柄排序；删除入口在事项编辑面板。离开时，未保存编辑和未回车添加的名称均会提示处理。准备清单随旅行保存、导出和导入，删除旅行也会删除所属清单。

行程卡片在路线、班次等主要信息下方显示预计预算，按币种分别合计。零金额正常显示；部分金额空白显示“含未估算”，全部空白显示“预算未估算”，没有预算条目时不显示。跨日行程和住宿标注“整条行程预算”，不会因为多个关联卡片而重复计入预算总表。

关于页面主要显示 `v0.1.18`，完整版本 `0.1.18+19` 仍用于安装与更新检查。


## 旅行总览（v0.1.7）

左侧“旅行总览”位于预备工作和日期列表之前，自动汇总当前旅行。点击日期名称进入当天，点击行程或预算费用明细打开现有编辑面板；宽窗口保持右侧编辑，窄窗口进入编辑页。修改保存后总览自动刷新，离开编辑仍会询问未保存内容。

- **旅行跨度**：首末安排日之间的日数，包含中间空缺和已记录的退房/结束日；不会因此补建空白日期。
- **已有旅行日**：与左侧日期列表一致，包括主动保留的空白日。
- **有行程天数**：实际存在每日行程节点的天数，包含住宿覆盖和跨日抵达。没有退房时刻、没有独立节点的退房日可以计入跨度，但不凭空计入有行程天数。
- **行程数量**：原始记录数量，跨日关联不重复计数，历史未安排记录也计入。

有出发日期时显示完整日期范围，跨年保留年份；无出发日期时只显示第 N 天。主体为默认可读的连续行程摘要，日期作为轻量标题并可点击跳转当天，不再逐日展开。空白日仅显示紧凑跳转与状态，真实日期不变。多晚住宿按原记录展示一次并注明覆盖日期/晚数；跨日交通一次展示起终点、班次和出发/到达日期，重复到访仍保留不同原记录。

地点直接显示在总览的对应行程条目中，点击已绑定名称打开原链接；活动按保存顺序显示各地点，标题不作为地点。重复到访仍归属于各自行程，不合并入口。总览中跨日交通集中显示起终点，住宿注明完整覆盖范围；当天页面的关联规则不变。总览不增加地图或完整地点资料卡。未绑定名称标明“搜索地点”，独立编辑按钮可进入行程补齐绑定，不强制填写。准备进度可点击进入预备工作清单，跳转仍检查未保存编辑。

预算在摘要之后按原币种显示紧凑总额，默认收起组成；展开币种、分类可查看所属行程的主要信息、金额和币种并进入修改。百分比以本币种已填写金额总计为分母，保留一位小数，舍入后合计可能略有差异；不混合币种，不换算汇率。0 正常显示，空金额单独计数、排除占比；全部未估算或合计零时明确显示无占比。未填写任何预算条目的行程另外计数。历史未安排、已完成行程仍计入预计预算；住宿/跨日关联只按原记录计费一次。

## 两端地点绑定、改名与打开

Windows 与 Android 共同升级到 **0.1.18+19**，同步/备份协议 7。旧客户端更换绑定可能丢失当前坐标，因此阻止协议 1–6 同步；兼容读取备份 1–7，不要用旧客户端编辑新数据库。Android 沿用原签名覆盖安装，不要卸载清除数据。

### 添加与绑定

游览／活动的标题可填“札幌市内观光”。在“活动地点”中逐条点击“添加地点”，输入地点名称，用上下箭头排序。“移除地点条目”只移除该行草稿；“解除绑定”只移除链接/位置、保留名称。两者都不会删除整条行程。交通仍分别管理起点、终点，住宿等仍为对应地点。

每个地点都有绑定入口。Windows 在默认浏览器搜索后复制分享内容，再返回主动粘贴；Android 可从外部地图系统分享至 HowDoI，或主动粘贴。不监听剪贴板、不抓取网页、不推断坐标。外部分享回传需核对旅行、行程与具体地点字段；多个链接需自行选择。无待绑定目标时先选择已保存行程与其地点；空的活动先在编辑页添加地点。系统回收后再次确认目标，未保存草稿无法恢复。

Windows 宽窗口中，点击绑定或更换后在右侧原编辑区域显示绑定页，左侧导航与中央行程保持可见。顶部返回箭头取消本次绑定，回到原草稿；确认后也回到原草稿。原行程表单及中央滚动位置保留。绑定页打开时尝试离开编辑，会先返回原行程；再次离开按未保存规则提示。窄窗口和 Android 使用独立绑定页面。

Windows 的“打开地图网页搜索”可能新增浏览器标签页。系统公开接口无法可靠指定上一次标签页，也无法识别其是否关闭或已导航到别处，本版不自动复用。需要复用时点击“复制搜索网址”，自行在已有标签页地址栏粘贴。复制操作不打开浏览器、不修改绑定；地图来源切换只影响新的搜索。不要把“已请求打开”理解为已复用标签页或页面加载成功。

确认绑定仅修改草稿，点击“保存行程”后才持久保存与同步。取消绑定或打开外部地图不自动保存。名称、地址与供应商可在绑定管理中核对；原链接不意味着已获得可靠坐标或已验证正确地点。

### 手工经纬度与当天地图

绑定页主要显示三个字段：地点名称、地图分享文字或链接、经纬度。名称默认带入当前地点，可修改绑定显示名称；不会擅自覆盖行程标题。分享内容可直接粘贴，多个链接才需选择。坐标可留空；可以同时填链接和坐标，最后只点一次“确认绑定到当前草稿”。地址与来源保留在折叠区，“去地图搜索”按需展开。

经纬度格式为 `40.828178925867995, 140.6934585811546`，严格按**纬度，经度**，纬度 -90～90、经度 -180～180，不自动交换。只录入 Google 地图复制的 WGS84 地点坐标；不使用视角中心，不将百度/高德原生坐标当 WGS84。格式通过不表示地点正确，需自己核对。链接来源与坐标来源独立记录，不自动解析分享链接或调用 Nominatim。

更换链接且保留了坐标输入时，必须选择“保留坐标，已核对仍为同一地点”或“清除坐标”。也可主动清空坐标字段；清除坐标不清除原链接。历史 previousPosition 永不自动启用。更换/清除/确认都只影响草稿，取消恢复原关联，保存后才同步。

当天日期标题下方显示可折叠地图，顺序沿用行程列表，同一活动按地点列表顺序。标点可打开简要名称、所属行程及原链接，也可进入编辑。相同坐标显示编号与其他到访数量，点击可逐条访问；“查看标点列表”也能访问所有条目。只显示本日当前有效且无需核对的位置；跨日班次在出发/到达日显示相应端点，住宿覆盖引用原记录。预算不会重复计算。

“已显示 X/Y 个地点”是有效坐标数/当天已有地点数；“补充坐标”可进入对应行程。已有链接无坐标并非“未绑定”，链接提示和坐标提示分别统计。没有有效坐标时只显示紧凑提示；没有地点时不留空地图。使用缩放按钮、拖动/触控和“显示全部地点”浏览；地图刷新不会提交草稿或修改行程时间。极区位置超出 OSM 投影范围时在边界展示并提示，原值保持不变。

底图由 OpenStreetMap 提供，署名常驻地图。只请求当前视野瓦片并保留 HTTP 缓存，不提供批量下载；没有 API 费用、服务器或定位权限。失败/超时可重试，也可继续文字编辑与原链接打开。服务可用性不保证，网络环境不同结果可能不同。

### 原链接与搜索偏好

在当天行程卡片、旅行总览的行程条目中，点击**地点名称**打开保存的原链接。没有链接但有文字时明确显示“搜索地点”，可通过地点操作菜单进入绑定；历史可靠坐标保留现有兼容能力。Windows 不再在当天顶部重复显示完整地点/地址卡片，仅在有未绑定名称时提示“有 N 个地点未绑定”，点击选择对应行程；全部绑定或没有地点时提示消失。两端使用同一规则。

修改地点名称后，原链接继续可打开，显示“名称已修改，请核对绑定地点”；不偷偷改为搜索，不算未绑定。绑定管理中可“确认仍是此地点”“更换绑定”或“解除绑定”，均随行程保存。修改活动标题不影响活动中的地点。更换地点链接不会把旧坐标当作新地点坐标，历史位置元数据保留。

“搜索地图偏好”独立设置国内/海外与 Google/百度/高德服务，留在本机，不同步覆盖另一台设备；未知地区先询问，不依据设备所在地判断。绑定了 Google 原链接也可正常设置搜索偏好，设置操作不会打开该链接、改写绑定或更新行程时间。“备用方式”提供当前地点重试、网页打开或复制。OS 接受请求只表示已请求打开，不代表网页加载成功或导航开始。

### 同名绑定复用

仅在同一次旅行中，名称去除首尾空白后**完全相同**、有唯一且无需核对的绑定时，保存前自动计算可复用范围。不会模糊匹配、翻译名称、跨旅行寻找或替换已有绑定。多个不同链接/来源有歧义时，在“复用已有绑定”中自行选择；已有待核对的同名绑定时保守暂停自动复用。

保存前显示数量、当前行程及其他受影响行程与地点名称。取消不写入任何记录；确认后统一检查版本并原子保存。预览期间任何已保存数据发生变化会要求重新核对，不部分写入。主动解除会持久保留“不自动复用”标记，再次使用须主动点“复用已有绑定”或重新绑定。更换某处绑定不更新其他已有绑定。没有独立地点库，复用后每条行程保有自己的地点数据。

多地点列表、绑定和解除标记随原行程同步与备份。整条行程最新更新为准：两端同时修改同一行程不同地点仍可能由较新的整条记录覆盖；不同记录分别合并。远端变化不覆盖正在编辑的草稿，保存时仍检查版本。

### 类型与兼容

类型菜单仅按当前旅行已保存、未删除的行程类型数量排序；同次数保持原固定顺序（历史类型追加保留），从未使用的类型排后。取消编辑、打开菜单不增加次数；打开期间不会重排，下次打开再按最新数据计算。同步数据一致后两端规则一致，不同步额外计数。新增行程默认选择当前旅行最多使用的类型；空旅行默认“游览/活动”。已有行程保留原类型，新增草稿开始后不因同步切换类型；下次新增或重新打开菜单才采用最新排序。旧类型名称与记录保持不变。

旧单地点活动兼容为一个地点：优先使用旧地址/位置，否则沿用旧名称，并保留原绑定；编辑保存后写入独立地点列表，不重复生成。列表最多 100 个地点，继续受原单条记录大小限制。旧费用名称隐藏但保留，不因界面迁移清空。

### 使用边界与验证

本版优化当前旅行类型默认值与连续总览，不新增 Nominatim、路线计算、自动规划、实际开支或 SPSir。共享代码和自动化测试覆盖两端布局、五个札幌地点逐个打开、改名核对、内联预算、排序、复用取消与并发保护；OS 打开接口为模拟。多地点在本机 HTTPS 客户端/服务端往返、重启与备份兼容通过独立数据验证，不等同红米 K70 真机 Wi-Fi 验证。本轮两端构建与验证范围见当前版本说明；未进行红米 K70 真机或真实 Wi-Fi 验证。

本轮未连接红米 K70，未验证真实手机系统分享、浏览器/地图唤起、系统回收及真实两端 Wi-Fi。此前 v0.1.13 的本机代理/VPN 环境中 Google、百度样本可显示对应地点，高德样本网页提示无法获取地点；本版未重复实测这些网页，不保证当前服务或国内直连可用。

官方说明：[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)、[百度网页调起](https://lbsyun.baidu.com/docs/webapi?title=mapadjustment/uri/web)、[高德 URI 搜索](https://developer.amap.com/api/uri-api/guide/search/search)、[Android 接收分享](https://developer.android.com/training/sharing/receive)。不需要密钥、自建服务器或付费套餐，外部网站可能有登录与访问限制。地图故障不影响本地文字路书、编辑、预算、备份和同步。

## 地图展开与同名复用

Windows 当天地图可点击“展开地图”，在应用标题栏下铺满可用区域；“返回行程”恢复原旅行、日期、滚动位置和编辑草稿，不触发保存。从标点进入编辑仍执行未保存提示。Android 地图布局不变。

同名地点复用现在也补齐已有相同原链接但缺少坐标的地点。只使用唯一、已确认且无需核对的当前坐标；不同来源/链接或不同坐标有歧义时不自动补齐，已有坐标不覆盖，主动解除标记继续生效。与 URL 一样在保存前预览并原子提交，两端共享规则。
