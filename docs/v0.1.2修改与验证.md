# HowDoI v0.1.2 Windows 修改与验证

日期：2026-10-13。版本来源为 `pubspec.yaml` 的 `0.1.2+3`；发布版本 `v0.1.2`，构建号 `3`。本轮只优化 Windows，不构建安卓新版、不实现 SPSir 接入或实际支出；SPSir 接口文档保留原样。

## 行为与交互

- 左侧“添加日期”仅创建并选中日期。第一次为第 1 天，以后取已有最晚旅行日 +1；不会打开编辑面板。
- 主动添加的日期以独立 `day` 记录的 `explicit: true` 标记保存。即使无行程、删除了全部行程、重开程序或导入备份，仍然显示。不会因旅行跨度自动生成中间空白日。
- 当天右下角“添加行程”归属当前日期。没有旅行日时先添加日期；新行程不能存成无日期记录。清空票面日期不清除所属旅行日。
- 移除左侧“待安排”。只有存在旧版 `day=0` 记录时，页面才出现日期分配入口。逐条分配，保留原始 ID、备注、预订资料和预计费用；酒店如需调整退房日会再次选择，不静默删除信息。处理完后入口消失。
- 使用统一近黑背景、深灰卡片/编辑栏、低饱和蓝色操作与焦点。日期选中有勾选，完成有勾选及删除线，错误显示文字。应用内输入框、下拉、日历、时间、设置、预算、关于和滚动条共用主题；原生标题栏固定暗色。Windows 文件选择器仍遵循系统外观。
- ≥1100 宽使用三栏，800–1099 保留左侧导航并使用独立编辑页面，更窄时折叠导航。

## 兼容和代码清理

保留 SQLite 原表结构与旧记录字段。首次打开旧数据库时保存同目录 `howdoi.db.pre-0.1.2-时间戳.db`，成功后才标记数据版本 3。支持读取/导入备份格式 1、2、3；新备份及同步协议为 3，以防旧客户端忽略显式空白日。旧 Windows/Android 协议 1、2 不能与本版同步。

经仓库调用检索，删除运行路径不再使用的 `Store.zone`、旧 `Store.dayItems` 排序实现及 `localInstants` 时区换算；排序回归测试改为覆盖真实主页使用的 `timeline`。时区数据校验仍用于兼容旧记录，因此保留 `timezone` 依赖及初始化。备份、逐记录同步、迁移和旧类型映射均保留。将已存在的间接依赖 `archive` 声明为直接依赖，用于更新包校验解压，没有引入额外更新框架。

## 更新与发布约定

唯一版本源：`pubspec.yaml`。Flutter 从这里生成 Windows EXE 版本资源；关于页读取同一个打包资源；Windows/Android 构建脚本从该文件提取发布号命名产物。本次只执行 Windows 构建。

更新源固定为 `https://api.github.com/repos/K1TAproject/HowDoI/releases/latest`，不读取开发电脑的 `D:` 路径。依据 [GitHub Releases REST API](https://docs.github.com/en/rest/releases/releases) 获取正式发布，忽略草稿和预发布。正式标签为 `vX.Y.Z`，Windows 附件名为 `HowDoI-X.Y.Z-windows-x64.zip`；ZIP 根目录直接包含 EXE、DLL、data，不能额外嵌套一个文件夹。不要修改已经发布的同版本附件；代码变化应递增版本。

使用 GitHub 附件的 SHA-256 digest，缺失时读取同次发布的 `SHA256SUMS.txt`。构建脚本生成该文件。更新程序限制 HTTPS 与 GitHub 下载域名、大小、跳转和超时，拒绝校验不符、路径穿越、符号链接、重复路径、缺失运行文件及包内版本不符的 ZIP。

安装过程：

1. 进入关于前先解决未保存编辑，并暂停本实例的同步写入。
2. 用户确认后下载，核对长度和 SHA-256，再解压到用户数据目录内的独立版本目录；不覆盖当前程序。
3. SQLite `VACUUM INTO` 保存一致性快照；复制快照给新版 `--update-probe` 试启动。副本读取及首帧成功后返回确认，不打开真实数据库，也不启动同步。
4. 再启动新版连接原数据。旧版等到首帧确认才交接；启动失败或超时则停止新进程，从快照事务恢复 records/settings，保留原窗口。新进程等旧版确认后再启动同步，避免抢占旧实例端口。
5. 成功后保留原程序和快照，创建本地启动脚本并打开新版目录，供用户创建快捷方式。旧便携 EXE 不被替换；已安装位置可在关于页查看。

发布步骤：运行构建脚本后，在项目 GitHub Releases 建立对应正式标签，上传 ZIP 与 `SHA256SUMS.txt`。普通 `git push` 只同步源代码，不会发布 ZIP。本轮没有自动推送或创建 Release。

## 验证边界

2026-10-13 首轮实际查询 GitHub latest API 返回 HTTP 404，应用提示“未找到可访问的正式发布版本”；最终重测返回 HTTP 403，显示“检查更新失败”，该网络测试按失败记录，未伪造通过。404 可能是尚未发布或仓库不可访问；403 的具体原因未进一步确认。两种结果都不能描述为“已更新”或“已是最新”。

已验证本机 HTTP 下载与失败场景、真实发布包解压及副本试启动。尚未验证真正发布更高版本后的 GitHub CDN 下载—用户确认—正式数据库交接—旧窗口退出全链路；此项需要未来正式 Release。没有模拟结果冒充线上更新成功。

Widget 渲染和交互验证不等于人工逐项操作全部 Windows 原生窗口；系统文件选择器、快捷方式固定、不同 DPI/辅助技术和真实跨设备同步仍需目标环境确认。更新包未作 Authenticode 签名；SHA-256 依赖可信 GitHub HTTPS 发布信息，不等同于 Windows 代码签名。断电、强制终止和其他实例同时写入不属于本轮自动恢复测试范围，数据库快照保留供恢复。
