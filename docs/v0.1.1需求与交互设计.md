# HowDoI v0.1.1 需求与交互设计

状态：产品需求与交互规则已确认，可作为 v0.1.1 开发基准（2026-10-13）。用户已授权实施 Windows 第一轮优化。

本文件汇总本轮已确认需求，作为 v0.1.1 后续开发依据。与 v0.1.0 文档冲突的交互规则，以本文件为准。第 6 节的存储、迁移和同步兼容性属于实施前需要核对的技术事项，不代表已验证兼容。

## 1. 目标与范围（已确认）

- 优先完善 Windows 端的实际规划与查看体验，之后再考虑安卓端迁移与适配。
- 降低录入负担，突出帮助安排和执行行程的关键信息，不再按资料完整性堆叠字段。
- SPSir 接入和实际开支记录降至最低优先级，不纳入本轮重点；现有 SPSir 接口文档保持原样。
- 需求讨论阶段已结束；当前按本文件实施 Windows 第一轮优化，版本目标 0.1.1。
- 原有预计预算并未被要求删除；本轮不主动扩展费用功能。

## 2. 输入原则（已确认）

### 2.1 标题与未确定内容

- 行程标题不作为必填项。
- 航班、火车等可由出发地与目的地自动生成显示标题。
- 其他行程可使用具体地点、活动内容或事件类型作为主页标题，不能因没有自定义标题而无法保存。
- 允许先保存未确定的安排，之后再补充预订信息。
- 低优先级字段不应挤占主要输入区域。座位号不是航班创建时的重点信息。

### 2.2 日期和时间

- 日期主要通过日历组件选择，尽量避免手动输入年月日数字。
- 时间主要通过选择组件输入，尽量避免手动输入数字。
- 取消面向用户的时区选择，包括旅行日与事件的时区设置。
- 起飞、到达等时间按相应地点的票面当地时间记录，不自动进行时区换算，不自动计算跨时区飞行时长。
- 跨日到达显示“次日”或具体到达日期；日期差的表达方式仍需覆盖超过一天和日期倒退的情况。
- 继续允许不确定日期或时间的规划，不强迫用户编造时间。

### 2.3 添加与编辑入口

- 添加入口和编辑容器的具体形式由开发时合理决定，无需为此反复确认。
- 可以在当天列表末尾或固定按钮添加行程，编辑可用右侧面板或弹窗。
- Windows 使用右侧编辑面板，编辑时仍能看见当天行程；窄窗口允许使用抽屉或弹窗。

### 2.4 旅行天数与日期（已确认）

- 新建旅行时不提前定死旅行天数，不以必填天数限制后续安排。
- 可以设置第一天的日期，并在规划过程中灵活延长或缩短旅行。
- 没有开始日期时，按“第1天、第2天、第3天……”显示。
- 未安排行程的天数不生成显示；不能仅因预设天数而出现大量空白日期页。
- 空白日只隐藏，不压缩日序。例如第 1、3 天有安排，第 2 天为空，只显示第 1、3 天；第 3 天的实际日期不变。
- 连住酒店覆盖的日期算作有安排，仍显示该天及当晚住宿。
- 新增更晚一天的行程即可延长旅行；末日安排全部删除或移走后自然缩短，不因缩短天数而隐式删除内容。
- 修改第一天日期时，未预订的规划随旅行日整体顺延，已有固定日期的机票、酒店等预订保留原日期并提示差异。

## 3. 主页（已确认）

- 以当天行程为主，按时间顺序展示。
- 航班号、车次、目的地、起止时间等重要信息直接在主页展示，不能必须打开详情才能查看。
- 使用带小时刻度的紧凑时间线，压缩空闲时段，不按全天 24 小时等比例铺满。
- 无具体时间的行程允许穿插在已定时行程之间，并手动调整位置；不强制放入独立的“当天待安排”区域，不自动赋予时间。
- 每天以“当晚住宿”区域显示酒店、位置及住宿日期。用户安排了具体入住或退房时间时，才另外显示相应时间线节点；连住酒店不重复占据每日时间线。
- 登机口、检票口、车厢座位在折叠的“补充信息”中录入。未填不显示；填写后，主页显示登机口、检票口和火车车厢座位，飞机座位保留在详情中。
- 主页保持简洁，未填写的次要信息不显示空标签或大量占位符。

## 4. 各类行程的信息优先级（已确认）

各类型的输入与主页展示已确认，详见第 7.1 至 7.7 节；整体布局和排序见第 5 节。

| 类型 | 主要录入区域及主页重点 | 次要内容的建议处理 |
| --- | --- | --- |
| 航班 | 出发机场与航站楼、到达机场与航站楼、起降日期时间、航班号 | 登机口可补充；航空公司、座位、订单号不占主要区域 |
| 火车/高铁 | 出发站、到达站、发到日期时间、车次 | 检票口、车厢和座位在预订后按需补充 |
| 交通/移动 | 起点、终点、预计耗时，适用于市内出行及长途自驾 | 交通方式与线路可选，不强求精确发到时间 |
| 长途汽车/轮渡 | 起终点车站或码头、出发与到达时间；可选班次 | 订单号等放补充信息 |
| 租车 | 取还车地点与日期时间，一次记录整个租期 | 公司、车型、订单等按需补充；每日驾车路线另用交通/移动记录 |
| 酒店 | 名称、位置、入住和退房日期、连住晚数 | 最早入住/最晚退房时间可补充；订单号不是主要输入 |
| 游览/活动 | 地点或活动内容、可选开始时间与预计停留时长 | 开放时间、预约提示按需补充 |
| 餐饮 | 店名或简单安排、可选时间与位置 | 不强制提前确定具体餐厅 |
| 购物/其他 | 简短内容、可选时间与位置 | 其余信息用备注承接 |

“主要信息”不等于“全部必填”。具体必填规则应以能保存草稿和不产生误导为标准。

## 5. 时间线与通用交互（已确认）

### 5.1 小时刻度与排序

- 使用紧凑的纵向时间线，左侧显示小时/具体时间，右侧显示事件卡片。
- 空闲时段压缩，不按全天 24 小时等比例铺满，避免少量行程产生大量空白。
- 有开始时间的行程按开始时间排序；同一时间保留用户顺序。
- 只有结束时间的行程不擅自推断开始时间。
- 已确认：未填时间的行程保留在时间线中的手动位置。
- 同一天内，无时间行程跟随前一个定时节点；该节点调整时间重新排序时，其后连续的无时间行程一起移动，但不获得虚构时间。用户可手动重新放置；位于第一个定时节点之前的无时间行程仍留在最前。
- 前一个节点删除或移到其他日期时，无时间行程留在原日、保持相互顺序，不自动跨日迁移；按剩余顺序重新归属前一个定时节点，没有则留在最前。
- 预约时间已填、计划开始时间未填时，按预约时间排序，但标注为“预约”，不将其写入计划开始时间；两者均有时按计划开始时间排序。
- 不自动修改行程时间，不因为拖动位置而隐式改变票面时间。

### 5.2 跨日和跨国行程

- 航班卡片分别标明出发与到达时间所属地点，避免将它们误认为同一时区。
- 航班、铁路、长途汽车和轮渡跨日到达在到达日显示关联信息，点击编辑原行程，不重复录入或计算预算（已确认）。
- 取消时区后，不对跨地交通使用“结束时刻早于开始时刻”的简单校验，也不据此推断时长或时间冲突。
- 当地时间排序是规划展示顺序，不承诺表示跨时区行程的真实时间先后；越过日期变更线等情况需要允许用户确认日期和归属。

### 5.3 时间选择组件

- 使用 24 小时制，可点选小时和分钟，无需键盘输入。
- 航班等精确时间必须支持任意分钟，不能只能选择 5 分钟或 15 分钟的倍数。
- 提供清除操作，使“未定时间”保持可用。
- 日期未确定时仍可选择旅行第几天，不为了使用日历而强迫先确定出发日期。

### 5.4 卡片信息层级

- 首层：开始/结束时间与路线或地点，类型只作辅助识别。
- 次层：航班号、车次、机场航站楼等执行信息。
- 备注和低频信息进入补充区域，不与关键时间争抢空间。
- 酒店展示和交通补充信息的规则已经确认，以第 3 节为准。

### 5.5 Windows 页面布局及通用交互

- 左侧选择旅行、待安排清单和日期；中间显示当天紧凑时间线及当晚住宿；右侧编辑选中的行程。窄窗口时允许以抽屉或弹窗承载编辑区。
- 日期列表只列有安排的日期，另有“添加日期/行程”入口，可以选择尚未显示的任意日期或第几天；取消空白编辑不生成日期页。
- 时间线保留小时标记和具体时间，压缩无行程的空白时段；不以卡片高度表示实际时长，无时间行程使用顺序连接，不画成精确时间点。
- 已定时行程调整时间后重新排序；拖动不修改票面时间，主要用于无时间行程及相同时间行程的顺序调整。
- 右侧主要字段默认展开，补充信息及预计预算折叠；预算仍可使用但不占据主要录入区域。
- 主页备注先显示一行，较长时可就地展开；关键航班、车次、起终点与时间不藏入备注或折叠区域。
- 延续明确的保存操作；有未保存修改时切换行程，提示保存、放弃或继续编辑，避免静默丢失输入。
- 日期采用日历、时间采用 24 小时小时/分钟选择，支持任意分钟及清空；时长使用小时/分钟选择，不要求输入起止时刻来代替时长。

## 6. 兼容边界（开发建议，实施前核对）

- 简化输入界面不等于删除已有记录的字段或内容。
- 已录入的座位、订单等信息应仍能查看和编辑，可以移至补充区域。
- 旧时区数据不应导致已有票面时间静默变化；旧记录如何保留原值、导入导出如何兼容，在实际实现前核对。
- 本轮不重写同步和存储架构；如新版本数据影响旧安卓客户端，需明确兼容范围后再交付，不能默认兼容。

### 7.1 航班输入与主页展示（已确认，2026-10-13）

- 右侧默认展开：航班号；出发机场、航站楼、出发日期/时间；到达机场、航站楼、到达日期/时间。起降分为两个清晰区块，按票面当地时间录入。
- 从某天添加时，出发日默认采用所选旅行日，允许调整；具体时间留空，不自动填当前时间。到达日默认同日但可更改，时间倒退时不自动推断次日。
- 不要求单独填写标题；有路线时用路线，没有路线时可用航班号，再缺省为“航班”。
- 提供简短备注；已预订状态保持容易找到。座位、订单号、航空公司、登机口进入补充信息，其中填写的登机口直接显示在主页。
- 主页显示路线、航班号、两端机场航站楼与起降时间；日期不同时显示各自日期，不计算跨时区时长。
- 机场允许直接输入名称或代码，不强制分别填写城市、机场全称和三字码，不引入在线航班查询。
- 跨日到达在到达日生成一条关联的到达提示，与原航班共用信息，点击仍编辑原航班，不要求再创建一条航班、不重复计算预算。到达日因此有内容，应在日期列表中显示。
- 转机每段航班分别记录，暂不增加联程订单分组。

### 7.2 铁路输入与主页展示（已确认，2026-10-13）

- 右侧主要区域：车次、已预订状态；出发站与出发日期/时间；到达站与到达日期/时间；可选备注。未定信息可以留空，标题由路线生成，缺省用车次或“铁路”。
- 补充信息默认折叠：检票口/站台、车厢、座位/铺位、席别、订单号。检票口和站台应可分别填写，不混为同一个值；座位/铺位允许自由文本以兼容卧铺及国外列车。
- 主页直接显示路线、车次、发到时间；跨日显示到达日期。填写后的检票口、站台、车厢和座位/铺位直接显示；席别、订单号留在详情。
- 跨日到达沿用航班关联提示，到达日因此显示；换乘列车每段单独记录，不增加联程分组。
- 高铁、普通火车和国外列车统一使用“铁路”类型，不要求先选列车子类型。

### 7.3 住宿输入与主页展示（已确认，2026-10-13）

- 已确认的基础规则：一次记录多晚住宿，每天在“当晚住宿”区域展示；实际计划入住/退房时间确定后才生成对应时间线节点。
- 右侧主要区域为住宿名称、地址/位置、入住和退房日期、已预订状态、可选备注。不单独要求标题，不要求同时填写城市、地区等重复位置字段。
- 日期用日历选择，未确定出发日期时选第几天；晚数由入住和退房日计算，无需重复填写。日期未齐全时仍允许保存草稿，不虚构晚数。
- “计划入住/退房时间”可选，表示用户打算到店/离店的时间；酒店规定的“最早入住/最晚退房时间”另放补充信息，不能据此自动生成用户行程。
- 补充信息包括酒店最早入住/最晚退房时间、房型、联系电话、订单号，均可留空；备注保持直接可用。
- 当晚住宿卡片显示名称、地址、入住至退房日期和晚数、预订状态；跨多日共用同一条记录，预算不重复计算。
- 退房日不再将原酒店列为当晚住宿，不生成“今日退房”关联提醒。仅填写退房日期或酒店最晚退房时间，不因此生成时间线节点或空白日期页；用户填写了计划退房时间时，才显示对应退房安排。
- 酒店、民宿、青旅统一使用“住宿”类型，不强制选择子类型。

### 7.4 交通/移动输入与主页展示（已确认，2026-10-13）

- 统一使用“交通/移动”（原讨论名为“市内交通”），同时覆盖市内出行和长途自驾，主要区域突出起点、终点和预计耗时。预计耗时尚不确定时允许留空，不要求为了保存草稿而编造时长。
- 交通方式不是必要字段，可以现场导航后再决定。步行、地铁、公交、打车、自驾或其他方式，以及线路/换乘说明、出发时间、备注均可选；不默认替用户选择交通方式。
- 不强制填写到达时间、精确班次或预订状态，不根据预计耗时自动改动其他行程时间。
- 主页以“起点 → 终点”和预计耗时为核心；方式和线路仅在填写后作为辅助信息显示，不显示“交通方式未填”等占位提示。有出发时间时显示时间，没有时按用户手动位置穿插。
- 起终点允许直接填写，也可从已有行程地点选取以减少重复输入；关联功能不作为必填步骤。
- 简单换乘允许在一条交通中记录，如“地铁 2 号线 → 10 号线”；也可按需手动拆成多条，不要求每次换乘都建事件。
- 长途汽车、轮渡及租车取还车流程使用第 7.7 节的专门类型。

### 7.5 游览与活动输入、主页展示（已确认，2026-10-13）

- 游览、展览、演出统一使用“游览/活动”类型，通过具体内容区分，不强制选择子类型。
- 主要区域：地点或活动内容、可选位置、计划开始时间、预计停留时长、备注。名称未确定时仍可用类型作为显示标题。
- 自由游览可只记录地点和预计停留时长，不强求具体开始/结束时间；有固定场次或预约时，可填写具体日期时间及预约状态。
- 开放时间、预约场次、计划到达时间含义不同，不将开放时间自动填作用户的计划时间。开放时间、预约信息和订单号进入折叠补充区域。
- 主页优先显示地点/活动、计划时间、预计停留时长和已填写的位置；已填的预约场次直接显示，便于执行行程。
- 不根据预计停留时长自动推迟后续安排。

### 7.6 餐饮、购物与其他行程（已确认，2026-10-13）

- 三类共用简洁的输入结构：店名/地点或安排内容、位置、计划开始时间、预计停留时长、备注。均允许先保存不完整的安排，不新增必填项。
- 餐饮允许只写“午餐”或“附近吃饭”，无需提前确定餐厅；有订位时在补充信息填写预约时间、状态和订单号，主页直接显示预约时间。
- 购物允许只记商场、街区或购物安排，购物清单写在备注，不增加商品明细录入功能。
- 其他用于休息、自由活动等，内容未填写时以类型显示。
- 主页显示安排内容、已填写的时间、预计停留时长和位置；不显示未填写字段。备注先显示一行，可就地展开全文。
- 餐饮、购物、其他保持可选类型以便识别，但不要求进一步选择子类型。

### 7.7 长途汽车、轮渡与租车（已确认，2026-10-13）

- 长途汽车、轮渡保留各自类型，共用类似铁路的输入布局：起终点车站/码头、发到日期时间，可选班次、已预订状态、备注。班次不作为必填项。
- 主页优先显示起终点、发到时间及已填写的班次；乘车口/登船口、站台、座位/舱位放补充区域，填写后在主页显示，订单号留在详情。
- 跨日到达沿用航班与铁路的关联显示，每段换乘分别记录，不重复预算。
- 租车一次记录整个租期：取车地点与日期时间、还车地点与日期时间，可选租车公司、已预订状态、备注；车型、订单号、联系电话等放补充信息。
- 租车主页在取车日和还车日显示同一记录的两个节点，分别突出地点和时间；租期中间日期不重复显示租车卡片，费用仅计算一次。
- 每日驾车路线作为交通行程单独安排，以起终点和预计耗时为重点；不要求逐日重复录入租车订单。
- 长途自驾也使用简洁交通表单，界面通用名称由“市内交通”改为“交通/移动”；方式仍可留空，不引入导航功能。

## 8. v0.1.1 验收场景

- 不输入自定义标题，仅选择类型或填写路线，也能保存并获得可辨认的主页标题。
- 添加航班时，机场、航站楼、起降时间和航班号在主要区域输入；主页无需展开即可查看。
- 创建航班时不需要填写座位号、订单号或选择时区。
- 跨日航班在到达当天显示关联信息，编辑仍指向原航班，预算只计算一次；转机各段分别记录。
- 铁路采用同样的跨日关联与分段记录规则；填写后的检票口、站台、车厢和座位/铺位直接显示在主页。
- 日期和时间都能完全通过鼠标选择，且允许清空和未定。
- 当天已定时行程有清晰的先后顺序和时间标识；无时间行程不会丢失或被自动赋予虚构时间。
- 无时间的“午饭后逛街”可以手动放在午餐之后，不要求先填写具体开始时间。
- 午餐时间改变时，其后无时间购物安排在同一天跟随排序；午餐删除或移到其他日期时，购物保留在原日，不被删除或自动跨日移动。
- 只有预约时间时按预约时间排序并显示“预约”，不擅自填入计划开始时间；拖动不改变票面时间。
- 小时刻度压缩空闲时段，无时间行程不显示虚构时间；主页关键资料无需打开编辑面板即可查看。
- 补充信息与预计预算默认折叠，备注可展开；未保存编辑切换时可保存、放弃或继续编辑。
- 连住酒店以当晚住宿展示；补充的登机口、检票口、火车车厢座位无需打开详情即可查看。
- 住宿不生成“今日退房”提醒；酒店规定的入住/退房时限不会被当作用户计划时间。仅在填写计划时间时显示入住/退房安排。
- 交通/移动只填起点、终点和预计耗时也能保存，主页突出路线与耗时，不要求先选择交通方式或线路。
- 长途汽车、轮渡支持跨日关联显示；租车一次记录取还车，费用只算一次，每日驾车路线独立安排。
- 游览/活动可只填地点和预计停留时长；有预约时主页显示预约时间，开放时间不会自动成为计划到达时间。
- 餐饮可只记“午餐”，购物清单可写在备注，其他行程可只记休息或自由活动；不要求补齐店名、时间或位置。
- 新建旅行无需预先填写天数；无开始日期时使用第几天显示，未安排行程的日期不产生空白页面。
- 第 1、3 天有安排而第 2 天为空时，只显示第 1、3 天且不压缩编号；可以从添加入口向未显示的日期安排行程。
- 调整出发日期后，未预订规划顺延，已有固定日期的预订保持原日期并显示差异；不得静默改动票面日期。
- 原有行程和补充信息不会因界面简化而丢失。

以上是需求目标，不代表功能已经开发或验证。
