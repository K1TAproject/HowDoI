# HowDoI v0.1.7 修改与验证

日期：2026-10-16。统一版本为 `pubspec.yaml` 中的 `0.1.7+8`，关于主要显示 `v0.1.7`。仅新增 Windows 旅行总览，不开发安卓、SPSir、实际开支或地图服务。

## 修改内容

左侧当前旅行导航在“预备工作”和日期列表前增加“旅行总览”。总览显示旅行名称、日期范围、跨度、已有旅行日、有行程天数、原始行程数量和准备完成进度。数据从当前 Store 读取，保存行程或预算后随现有通知刷新；没有重复录入字段、数据迁移、新依赖或配置系统。

按天摘要使用现有行程关联节点和排序算法，显示时间、路线、班次、住宿覆盖及跨日关系。酒店在同一天已有入住节点时不再重复列住宿覆盖项。日期文字可以进入当天，箭头展开/折叠；行程和预算明细打开现有编辑面板，窄窗口使用原编辑页。所有离开操作继续经过现有未保存检查。

地点采用明确填写的起终点、地址/位置和住宿名称；普通活动标题不被推测为地点。地点清单仅合并首尾空白处理后完全同名的条目。日期路线保留重复到访；同一交通记录的起终点才表示交通连接，不把相邻行程推断为交通。跨日航班将起点放在出发日、终点放在抵达日；租车区分取还车安排；住宿覆盖日不凭空生成新到访。历史未安排记录可进入地点名称清单，但不插入日期顺序。

预算继续调用现有 `Budget` 原币种汇总，每条原始行程只计算一次。每种币种可展开分类金额、百分比及费用组成，明细包含所属行程、名称、金额和币种，可进入编辑。完成勾选不影响预算。没有预算条目不显示虚构币种；0 正常显示；空金额单独计数、不参与占比；全部未估算或合计零显示“无占比”。历史未安排记录仍计入总计，并在明细标注。

没有引入地图、自动规划、总览导出或实际开支功能。生产代码新增 `lib/overview.dart`，原导航只增加总览状态和入口；原排序、关联和预算计算代码不变。安装验收脚本改为从 pubspec 读取新版版本，避免新版本测试仍硬编码 0.1.6。

## 明确口径

- **旅行跨度**：首末安排日（包括已有旅行日及原记录的开始/结束日）之间的日数，包含中间空缺。已记录退房日可计入跨度，不因此创建日期。
- **已有旅行日**：沿用 `Store.visibleDays`，与左侧日期列表一致，包含主动保留的空白日。
- **有行程天数**：现有 `planNodes` 中正数日期的去重数量，包含住宿覆盖和跨日抵达。未生成节点的退房日不虚增此数量。
- **行程数量**：非删除的原始行程记录数，关联卡片不重复计数，包含未安排历史记录。
- **预算未估算**：空金额按费用笔数统计，未填写任何预算的行程另外统计；二者合计对应原预算界面的未估算范围。百分比只以同币种已填写金额为分母，按一位小数四舍五入，不同币种没有共同分母。
- 无出发日期只显示“第 N 天”，跨年日期范围保留完整年份。空旅行显示明确空状态，不补建旅行日。
